# CSV Import Pipeline Audit Report

| file | problem | before | after | rationale | impact |
| --- | --- | --- | --- | --- | --- |
| `server/process-upload.ts` | CSV ingestion relied on `xlsx.sheet_to_json`, coerced everything to `any`, and wrote rows without validation, transactions, or summary reporting. | Uploaded CSVs were parsed as if they were XLSX, decimal commas turned into `NaN`, dates defaulted to `Date.now()`, and the function returned only `{ success, totalProcessado }`. | Replaced by orchestrator that streams CSV content through a hardened parser, validates with Zod, wraps persistence in a transaction, and returns a detailed `ImportSummary`. | Ensure pt-BR numerics/dates survive parsing, stop silent data loss, and expose actionable telemetry for dashboards. | Correct metrics reach the DB; importer can be dry-run and monitored, eliminating “all zeros” dashboards. |
| `server/routers.ts` | Mutation `dados.importar` duplicated ad-hoc parsing/validation, used `console.log`, and never surfaced skip reasons or dry-run capability. | Hundreds of lines re-implementing CSV parsing, bypassing type safety, and mutating DB row-by-row with bare inserts. | Mutation now delegates to `processarUpload`, accepts optional CSV inputs + `dryRun`, and returns structured summary + counts expected by UI. | Single source of truth for import behaviour and uniform summary semantics. | Front-end receives consistent metrics, backend maintains one import path, greatly reducing regression surface. |
| `server/upload-route.ts` | Upload endpoint ignored dry-run intent and logged errors to `console`. | Only accepted multipart payloads, always mutated DB, and leaked stack traces via `console.error`. | Added query-string dry-run parsing and routed errors/info through structured logger. | Align HTTP endpoint with importer capabilities and logging policy. | Safer uploads (no accidental writes) and cleaner observability hooks. |
| `drizzle/schema.ts` & `drizzle/0005_e2e_csv_import.sql` | Tables lacked fingerprints/unique constraints; repeated imports duplicated records and columns for QR-code/tabela preço were missing. | `movimentacoes`/`estoque` had no natural key or storage for optional metadata, so reimports inflated metrics. | Added deterministic SHA-256 `fingerprint` columns, unique indexes, and optional fields; migration backfills existing rows. | Required to make upserts idempotent and keep schema aligned with parsed payloads. | Dashboards become stable under re-import and additional metadata is preserved. |
| `server/uploadCamadas.ts` | Background uploader emitted raw `console.log`/`console.error` lines. | Logs were unstructured and missed retention policy. | Replaced prints with shared `logger` calls and contextual metadata. | Consistent observability across synchronous and async import flows. | Easier to trace upload jobs and correlate with summaries. |
| `server/importer` (new) | No central parser existed to normalize headers, decimals, aliases, or report skip reasons. | Each caller implemented bespoke parsing with no BOM handling, alias map, or granular errors. | Introduced reusable utilities (`constants`, `utils`, `parser`, `row-validators`, `importer`) that encapsulate header aliasing, pt-BR number/date parsing, boolean normalization, and structured error collection. | Codifies import contract in one place, fully typed, and testable. | CSV ingestion is resilient to BOMs, accents, mixed separators, and feeds precise diagnostics back to UI/logs. |
